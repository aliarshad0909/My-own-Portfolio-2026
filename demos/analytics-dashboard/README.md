# Northwind Supply Co. — analytics dashboard demo

A working business analytics dashboard built as a portfolio demonstration by
Ali Arshad.

**Northwind Supply Co. is a fictional business.** Every figure is synthetic data
generated deterministically in the browser. Nothing here is a real company's
trading history, and the numbers are not benchmarks.

Project 02 of the portfolio expansion.

## What actually works

- **Date ranges** — 30 days, 90 days, 12 months, all time, or a custom range. Every metric, chart and table recalculates from the filtered rows.
- **Period-on-period comparison** — each KPI shows the change against the immediately preceding window of the same length, computed from the data rather than stored.
- **Revenue chart** — hand-drawn SVG line chart with day, week and month bucketing, a hover readout of exact values, and empty buckets preserved so gaps are never hidden.
- **Breakdowns** — revenue by channel and by region with shares that total 100%.
- **Product performance** — units, revenue, gross profit, margin, stock on hand and days of cover, sortable on every column in both directions.
- **Inventory signal** — days of cover is `on hand ÷ units sold per day` over the selected window; under 30 days is flagged.
- **Channel filter** — combinable with any date range.
- **CSV export** — a real RFC 4180 file, generated from the current view and downloaded via a Blob.

Every chart has a screen-reader table alternative, so the numbers are never
locked inside a picture. Sortable columns expose `aria-sort`.

## The dataset

Generated by `src/data/generate.ts` from a fixed seed: 24 products across 5
categories, ~7,100 order lines, 18 months to 30 June 2026, 5 sales channels and
6 regions. The shape is deliberately business-like — weekday rhythm, steady
growth, a Q4 lift, wholesale buying more units at lower prices — so the charts
exercise real conditions rather than smooth noise.

Changing the seed or the catalogue in that file changes everything downstream.
There is no server, no database and no tracking.

## What is deliberately not here

| Area | Reality |
| --- | --- |
| Data source | Synthetic and in-browser. A real deployment would query a warehouse or an API. |
| Auth | None. Anyone with the URL sees the dashboard. |
| Persistence | None. Filters reset on reload. |
| Forecasting | None. Nothing here predicts future performance. |

The aggregation layer in `src/lib/analytics.ts` takes plain arrays and has no
React or browser dependencies, so it could run server-side against a real
database unchanged.

## Running it

Requires Node.js 22.18 or newer.

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # static files in dist/
npm run typecheck
npm test           # 15 unit tests
```

End-to-end tests need a served build and Playwright:

```bash
npm run build && npx serve dist
npx playwright install chromium
node e2e/smoke.mjs http://localhost:3000
```

## Tests

| Suite | Count | Covers |
| --- | --- | --- |
| `tests/analytics.test.ts` | 15 | Dataset determinism and validity, inclusive day counting, previous-period maths, ISO week bucketing, totals against manual sums, channel filtering, empty-bucket preservation, share totals, margin and days-of-cover maths, delta guards, compact money formatting, sorting with nulls last, CSV escaping. |
| `e2e/smoke.mjs` | 14 | Range switching, granularity, chart hover readout, channel filtering, KPI deltas, column sorting and `aria-sort`, custom ranges, a real CSV download, chart table alternatives, runtime errors. |

All pass as of the last commit.

## Technology

React 19, TypeScript, esbuild. No charting library — the line chart, bars and
sparklines are SVG generated from the data, which is the point of the
demonstration. No UI framework. Fonts (Inter, JetBrains Mono) load from Google
Fonts under the SIL Open Font License.

Build output: ~213 KB JavaScript, ~7 KB CSS.

## Deploying

Static output, so any host works. `vercel.json` is included. Deploy as its own
Vercel project with root directory `demos/analytics-dashboard`, then set
`liveUrl` on the project record in the portfolio's `lib/projects.ts`.
